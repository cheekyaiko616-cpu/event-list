# 毎日の自動取得：作業の手順書

毎日（11:59 JST）の自動の作業は、この手順書のとおりに進める。手順を変えたいときは、この文書を直す。ただし、作業の指示文（予約作業に入れた文章）と食い違うときは、指示文を優先する。

## 1. 調べる対象を読む
- `watchlist.json` の `tabs` を読む。タブごとに、`tabName`（アプリのタブ名と同じ）と `watch`（欲しい日程）がある。
- `feed.json` の今の内容も読む（前回との差を見るため）。

## 2. 公式情報で調べる
- 公式サイト・主催者の発表を第一にする。報道だけのものは、`note` に「報道ベース」と書く。
- X（旧Twitter）は調べる対象にしない（読めないため）。`watch` に「公式X」「Xで確認」などと書かれていても、その部分は無視して、公式サイト・主催者のページ・ニュースだけで調べる。Xのことは、報告にも書かない。
- 推測で日付を書かない。分からないものは、空にする。

## 3. feed.json に書く
各件に `id`・`tabName`・`title`・`date`・`end`・`place`・`source`（出典。必須）・`url`・`note`・`checkedAt`（確認した日）を書く。日程が未定のものは `date` を空にする。

### 申し込み・期限の日付（`dates`）
- 書く対象は、`watchlist.json` の各タブにある `kinds` で決まる。`kinds` は、利用者がアプリのタブの編集画面で選んだ「自動で取り込む日付」の種類の並び。
  - `kinds` が空、または無いタブ：`dates` は書かない（開催日だけ）。
  - `kinds` があるタブ：そこに含まれる種類の日付だけを書く。含まれない種類は、公式に載っていても書かない。
- 各件に `dates` を書く。形は `{ "kind": "...", "date": "YYYY-MM-DD", "note": "..." }` の並び。
- `kind` は次の5つだけ。
  - `open` 申込開始 ／ `close` 申込締切 ／ `result` 当落発表 ／ `pay` 入金期限 ／ `other` その他（一般発売の開始日など）
- 公式が日付を発表しているものだけを書く。未発表のものは書かず、`note` に「当落発表は未発表」のように残す。
- 先行（会員・FC・プレイガイド）と一般で日付が違うときは、`note` に何の先行かを書く（例：「会員最速先行 23:59まで」。`note` は40文字まで）。同じ種類を複数書いてよい。
- 1件につき最大8つ。日付は、締切が過ぎたものも消さずに残す。
- 公式の発表で日付が変わったら、書き換える。
- アプリ側でも、タブの設定にない種類は取り込まない。作業の側でも、同じ決まりに合わせる。

### 古い予定の整理
- `feed.json` の `items` のうち、**終わって1年（365日）たった予定は消す**。終わった日は `end`、`end` が空なら `date`。アプリの「終わって1年で消す」決まりと同じにする。
- `date` が空の予定（日程未定）は、消さない。
- 消した件数と題名は、最終報告に書く。`updates.json` の履歴には書かない。

## 4. updates.json に履歴を足す
- **新規または変更が1件以上あった日だけ**、`entries` の先頭に、その日の1件を足す。形は既存の件のとおり。
  - `date`・`summary`・`added`（`title`・`tab`・`when`）・`changed`（`title`・`field`・`before`・`after`）だけを書く（`field` は何が変わったかの名前。「日程」「場所」「申込期間」など。LINEの通知に「日程：変更前 → 変更後」の形で出る）（変更なしの件数や、確認できなかったことは、書かない）
  - 同じ日付の記録が既にあれば、その記録を更新する（1日1件）。
- 申し込み・期限の日付が増えた・変わったときは、`changed` に書く（例：`before`「申し込みの日付なし」→ `after`「申込開始 10/20 ／ 申込締切 10/27」）。
- **新規も変更も0件の日は、`updates.json` を変更しない**（「変更なし」の記録は足さない。確認できなかったことも、記録しない）。
- 足したあと、`entries` が **50件を超えたら、日付の古いものから削除して50件にそろえる**。削除するのは `updates.json` の記録だけ。履歴を50件にそろえるときに、`feed.json` の `items` は消さない（アプリの予定は消えない。予定を消すのは上の「古い予定の整理」だけ）。

## 5. LINE に知らせる（任意）
- `updates.json` に今日の記録を足した、または近い申込締切があるときだけ、`python3 tools/line_notify.py` を実行する（送り先の鍵は環境変数。ファイルには書かない）。
- 送る内容は、`updates.json` の今日の記録と、申込締切のちょうど3日前になったものだけ（毎日は送らない）。
- 鍵が設定されていなければ、送らずに内容だけ表示される。それは失敗ではない。

## 6. 書き込む
- **毎日必ず**、`feed.json` の最上位の `checkedAt` に、今日（日本時間）の日付 `YYYY-MM-DD` を書く。**変更が1件もなかった日も書いて、push する。**
  - これが、取得が動いているかを見分ける唯一の印。LINE通知（12:30）は、この日付が2日以上前だと「取得が止まっている可能性」を知らせる。
  - 取得に失敗した日（サイトに全くつながらない等）は、書かない（書くと、止まっているのに動いているように見える）。
  - 最上位の `updatedAt` は、これまでどおり「中身を変えた日」。`checkedAt` とは別。
- 書き込むのは `feed.json` と `updates.json` だけ。`main` に直接 push してよい。
- アプリのコード・`watchlist.json`・`plant-app` 系は、触らない。
- push できなかったときは、その旨を最終報告に書いて止める。
