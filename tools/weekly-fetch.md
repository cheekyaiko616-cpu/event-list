# 毎週の自動取得：作業の手順書

毎週（月曜 11:59 JST）の自動の作業は、この手順書のとおりに進める。手順を変えたいときは、この文書を直す（作業の指示文そのものは変えなくてよい）。

## 1. 調べる対象を読む
- `watchlist.json` の `tabs` を読む。タブごとに、`tabName`（アプリのタブ名と同じ）と `watch`（欲しい日程）がある。
- `feed.json` の今の内容も読む（前回との差を見るため）。

## 2. 公式情報で調べる
- 公式サイト・主催者の発表を第一にする。報道だけのものは、`note` に「報道ベース」と書く。
- X（旧Twitter）は読めない。読めなかったものは、更新履歴の `uncertain` に書く。
- 推測で日付を書かない。分からないものは、空にして `uncertain` に書く。

## 3. feed.json に書く
各件に `id`・`tabName`・`title`・`date`・`end`・`place`・`source`（出典。必須）・`url`・`note`・`checkedAt`（確認した日）を書く。日程が未定のものは `date` を空にする。

### 申し込み・期限の日付（`dates`）
- 書く対象は、`watchlist.json` の各タブにある `kinds` で決まる。`kinds` は、利用者がアプリのタブの編集画面で選んだ「自動で取り込む日付」の種類の並び。
  - `kinds` が空、または無いタブ：`dates` は書かない（開催日だけ）。
  - `kinds` があるタブ：そこに含まれる種類の日付だけを書く。含まれない種類は、公式に載っていても書かない。
- 各件に `dates` を書く。形は `{ "kind": "...", "date": "YYYY-MM-DD", "note": "..." }` の並び。
- `kind` は次の5つだけ。
  - `open` 申込開始 ／ `close` 申込締切 ／ `result` 当落発表 ／ `pay` 入金期限 ／ `other` その他（一般発売の開始日など）
- 公式が日付を発表しているものだけを書く。未発表のものは書かず、`note` に「当落発表は未発表」のように残す。
- 先行（会員・FC・プレイガイド）と一般で日付が違うときは、`note` に何の先行かを書く（例：「会員最速先行 23:59まで」。`note` は40文字まで）。同じ種類を複数書いてよい。
- 1件につき最大8つ。日付は、締切が過ぎたものも消さずに残す。
- 公式の発表で日付が変わったら、書き換える。
- アプリ側でも、タブの設定にない種類は取り込まない。作業の側でも、同じ決まりに合わせる。

## 4. updates.json に履歴を足す
- `entries` の先頭に、その日の1件を足す。形は既存の件のとおり。
  - `date`・`summary`・`added`（`title`・`tab`・`when`）・`changed`（`title`・`before`・`after`）・`unchanged`（件数）・`uncertain`（確認できなかったこと）
- 申し込み・期限の日付が増えた・変わったときは、`changed` に書く（例：`before`「申し込みの日付なし」→ `after`「申込開始 10/20 ／ 申込締切 10/27」）。
- 何も変わらなかった週も、「変更なし」の1件を足す。

## 5. 書き込む
- 書き込むのは `feed.json` と `updates.json` だけ。`main` に直接 push してよい。
- アプリのコード・`watchlist.json`・`plant-app` 系は、触らない。
- push できなかったときは、その旨を最終報告に書いて止める。
